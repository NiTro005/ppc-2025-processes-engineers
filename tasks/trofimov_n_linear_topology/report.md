## 1. Введение

В данной работе рассматривается задача из области топологий сетей передачи данных. Требуется реализовать виртуальную топологию взаимодействия процессов с использованием средств MPI по работе с коммуникаторами и обеспечить возможность передачи данных от любого выбранного процесса к любому другому.

В рамках варианта была реализована линейная топология передачи данных. При этом не использовались специализированные функции создания топологий MPI (`MPI_Cart_Create`, `MPI_Graph_Create`), а вся логика взаимодействия была реализована вручную на основе стандартного коммуникатора `MPI_COMM_WORLD`.

Целью работы является изучение принципов организации виртуальных топологий, а также анализ накладных расходов межпроцессного взаимодействия по сравнению с последовательной реализацией.

## 2. Постановка задачи

Реализовать виртуальную линейную топологию сети передачи данных с использованием MPI. Необходимо обеспечить передачу данных от любого выбранного процесса к любому другому процессу без применения функций `MPI_Cart_Create` и `MPI_Graph_Create`.

Пусть имеется набор из `P` процессов, образующих логическую линейную структуру с рангами от `0` до `P-1`. Передача данных осуществляется последовательно через промежуточные процессы.

**Входные данные:**

* `source` — ранг исходного процесса
* `target` — ранг целевого процесса
* `value` — целочисленное значение для передачи

**Выходные данные:**

* Переданное целочисленное значение, доступное всем процессам после завершения вычислений

**Ограничения:**

* `0 ≤ source, target < P`
* `value ≥ 0`

## 3. Базовый алгоритм (последовательный)

В последовательной версии алгоритма не используется параллелизм и межпроцессное взаимодействие. Результат просто присваивается равным входному значению `value`. Данная реализация используется как эталон для проверки корректности и оценки накладных расходов параллельной версии.

## 4. Схема распараллеливания

Для параллельной версии используется библиотека MPI и линейная топология обмена:

* Каждый процесс соответствует одному рангу в `MPI_COMM_WORLD`.
* Значение передаётся от `source` к `target` последовательно, через все промежуточные ранги.
* Направление передачи определяется автоматически в зависимости от взаимного расположения `source` и `target`.
* Для передачи используются блокирующие операции `MPI_Send` и `MPI_Recv`.
* После получения значения целевым процессом выполняется рассылка результата всем процессам с помощью `MPI_Bcast`.

Таким образом, каждый промежуточный процесс участвует в передаче данных только при нахождении между `source` и `target`.

## 5. Детали реализации

* **Структура кода:**

  * `ops_mpi.*` — реализация MPI-версии алгоритма;
  * `ops_seq.*` — последовательная версия;
  * модуль `common` — описание входных и выходных данных.
* Реализована обработка граничных случаев, включая ситуацию `source == target`.
* Выполняется проверка корректности входных данных (валидность рангов).
* Используется минимальный объём памяти, так как передаётся только одно целочисленное значение.

### 7.2 Производительность

Результаты измерений времени выполнения приведены в таблице ниже.

Для расчёта ускорения и эффективности за базу была взята последовательная версия (SEQ, 1 процесс).

| Режим | Число процессов | Время (pipeline), с | Ускорение | Эффективность |

| SEQ   | 1               | 0.00000011          | 1.00      | —             |

В таблице приведены усреднённые значения времени, полученные по нескольким запускам. Видно, что ускорения при использовании MPI не наблюдается. Наоборот, с ростом числа процессов время выполнения увеличивается. Это связано с тем, что объём передаваемых данных очень мал, а накладные расходы на инициализацию MPI и межпроцессные передачи значительно превышают полезные вычисления. Последовательная версия демонстрирует наименьшее время выполнения из-за отсутствия коммуникационных затрат.

## 8. Выводы

В ходе выполнения работы была реализована задача передачи данных в линейной топологии с использованием MPI и последовательного алгоритма.

Последовательная версия показала наилучшее время выполнения, так как не содержит накладных расходов на обмен сообщениями. MPI-реализация корректно работает для любого направления передачи, однако при малом объёме данных демонстрирует ухудшение производительности при увеличении числа процессов.

Таким образом, можно сделать вывод, что использование MPI оправдано для задач с большим объёмом вычислений или данных, тогда как для простых операций последовательный подход является более эффективным.
